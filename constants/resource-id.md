# 자원 식별자 상수 (접두사·글자·길이)

> 상태: 아래 **값은 확정**이다. 이 값을 파일로 두는 형식과, 값에서 Kotlin·Go·React 상수를 만드는 방법은 **아직 정하지 않았다** (백엔드·프론트엔드·Go 담당이 정한다).
>
> 함께 읽을 문서: [23번(자원 이름 규칙) — resource-naming.md](../rules/resource-naming.md)

## 이 문서가 있는 이유

자원 id를 만들고 검사하는 코드는 Kotlin(API 서버), Go(인프라 실행 엔진), React(웹 콘솔) 세 곳에 있다. 세 곳이 접두사 목록·글자·길이를 각자 들고 있으면 한쪽만 바뀌어 어긋난다. 그래서 값의 원본을 이 저장소 한 곳에 두고, 세 언어의 상수를 여기서 만든다.

값을 바꿔야 하면 이 문서를 먼저 고치는 PR을 올리고, 세 분야 담당이 확인한 뒤 합친다. 이미 정한 접두사는 바꾸지 않는다.

## 1. id의 모양

```text
{접두사}-{무작위 부분}
```

- 접두사와 무작위 부분 사이에만 하이픈(`-`)을 쓴다
- 무작위 부분에 쓰는 글자는 아래 32개뿐이다

```text
0123456789abcdefghjkmnpqrstvwxyz
```

- 헷갈리는 `i`, `l`, `o`, `u`는 뺐다. 사람이 id를 읽고 받아 적을 때 `1`/`l`/`i`, `0`/`o`가 헷갈리지 않게 하려는 것이다
- 무작위 부분은 **순수한 난수**다. 생성 시각을 담거나 순서대로 커지는 방식(ULID 등)은 쓰지 않는다. 만든 시각이 드러나고 다음 id를 추측할 수 있기 때문이다
- 난수는 암호학적 난수 생성기로 만든다: Kotlin `SecureRandom`, Go `crypto/rand`. Kotlin `Random`, Go `math/rand`는 쓰지 않는다

## 2. 무작위 부분의 길이

| 대상 | 길이 | 경우의 수 |
|---|---|---|
| 서비스 자원, 사용자, 팀 | 12자 | 2^60 (약 1.15×10^18) |
| 하위 자원 | 8자 | 2^40 |

- 12자로 충분한 이유: id가 겹치면 서버가 다시 뽑으면 되므로 드물기만 하면 된다. id를 안다고 권한이 생기지 않고(모든 요청은 권한 판단을 거친다), 볼 수 없는 자원은 404로 숨긴다. 그래서 "알면 통과되는 값"(세션 id 등)에 요구하는 길이는 필요 없다
- 더 줄이지 않는 이유: id 길이는 나중에 늘리기가 매우 어렵다

## 3. 접두사 목록

### 서비스 자원 (GRN을 갖는다)

| 접두사 | 자원 | 예 |
|---|---|---|
| `vm` | VM (인스턴스) | `vm-k3m9x2p7q4ta` |
| `fn` | 서버리스 함수 | `fn-6d2r8t5y3n7e` |
| `db` | 데이터베이스 | `db-k3m9x2p7q4ta` |
| `app` | 원터치 배포의 앱 | `app-k3m9x2p7q4ta` |

### 소유 주체 (GRN이 없고 자기 id만 가진다)

| 접두사 | 대상 | 예 |
|---|---|---|
| `user` | 사용자 | `user-8hq2m5v7c3kx` |
| `team` | 팀 | `team-4p8w2k9m1xza` |

### 하위 자원 (부모 GRN과 함께 쓴다)

| 접두사 | 하위 자원 | 부모 | 예 |
|---|---|---|---|
| `snap` | 스냅샷 (직접 만든 것, 자동 스냅샷) | VM | `snap-7qz3m8k2` |
| `port` | 포트포워딩 | VM | `port-5q8w3n7z` |
| `domain` | HTTPS 도메인 연결 | VM, 서버리스 함수, 앱 | `domain-4k8m2q9t` |
| `fwrule` | 방화벽 규칙 | VM | `fwrule-7m3k9p2x` |
| `trigger` | 트리거 (HTTP, 예약) | 서버리스 함수 | `trigger-5n3w7r2x` |
| `version` | 함수 버전 | 서버리스 함수 | `version-9c4m6k2p` |
| `backup` | 백업 | 데이터베이스 | `backup-3x7q9m4k` |
| `service` | 서비스 (앱 안의 실행 단위) | 앱 | `service-6t2p8w4z` |
| `env` | 환경 (production 등) | 앱 | `env-2k9m5x7q` |
| `deployment` | 배포 기록 | 앱 | `deployment-8q4n6c3v` |

- `domain`처럼 같은 종류의 하위 자원이 부모 종류 둘 이상에 붙을 수 있다. 이때도 id 모양은 같고, 부모는 요청에 적힌 부모 GRN으로 정한다

## 4. 접두사를 정하는 규칙

1. 영어 소문자 단어만 쓴다. 하이픈과 숫자를 넣지 않는다
2. 서비스 자원, 하위 자원, 사용자, 팀을 통틀어 모든 접두사가 서로 달라야 한다
3. 권한 판단의 동작 이름 앞부분과 같게 쓴다. 예: `vm-` ↔ `vm.delete`, `snap-` ↔ `snap.create` ([22번(권한 판단 Layer)](../rules/authorization.md))
4. 한 번 정한 접두사는 바꾸지 않는다
5. 새 서비스나 기능을 설계할 때 그 하위 자원과 접두사를 [23번 문서](../rules/resource-naming.md)의 서비스별 목록과 이 표에 함께 추가한다

## 5. GRN 형식

| 대상 | 형식 | 예 |
|---|---|---|
| 서비스 자원 | `grn:{소유자 id}:{자원 id}` | `grn:team-4p8w2k9m1xza:vm-k3m9x2p7q4ta` |
| 하위 자원 | `{부모 GRN}/{하위 자원 id}` | `grn:team-4p8w2k9m1xza:vm-k3m9x2p7q4ta/snap-7qz3m8k2` |

- 구분자는 `:`과 `/`다. id 안에는 `:`와 `/`가 나오지 않으므로, 첫 `/`에서 자르고 `:`로 나누면 정확히 나눠진다
- 소유자 칸에는 사용자 id 또는 팀 id가 들어간다
- GRN 문자열을 코드에서 직접 자르지 않는다. GRN 파서만 쓴다
- GRN 파서는 엄격한 정규식으로 **문자열 전체**를 검사하고, 통과하지 못하면 거절한다. 파서는 자원 id만 돌려주고 소유자 칸의 값은 파서 밖으로 꺼내지 않는다 (소유자 칸으로 권한을 판단하는 사고를 구조로 막는 장치다. [23번 문서](../rules/resource-naming.md) 3장)

## 6. 맞는 id와 틀린 id

| id | 판정 | 이유 |
|---|---|---|
| `vm-k3m9x2p7q4ta` | 맞음 | 접두사 + 12자, 허용된 글자만 |
| `snap-7qz3m8k2` | 맞음 | 하위 자원은 8자 |
| `VM-k3m9x2p7q4ta` | 틀림 | 대문자 |
| `vm-k3m9x2p7q4tl` | 틀림 | `l`은 쓰지 않는 글자 |
| `vm-k3m9x2p7` | 틀림 | 서비스 자원은 12자인데 8자다 |
| `k3m9x2p7q4ta` | 틀림 | 접두사가 없다 |
| `vm_k3m9x2p7q4ta` | 틀림 | 구분자는 하이픈이다 (Kubernetes·Proxmox 이름 규칙과 맞추기 위해 밑줄은 쓰지 않는다) |

## 7. 아직 정하지 않은 것

- 이 값을 담는 파일 형식, 세 언어의 상수를 만드는 방법, 생성한 코드를 저장소에 커밋할지
- 정규식을 어떤 표기로 둘지 (이 문서의 값 표가 기준이다)
- 사용자가 정하는 이름(`name`)의 글자·길이·예약어 규칙 (백엔드 담당)
