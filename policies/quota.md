# 27번(사용량 할당량) — 자원 한도 규칙

> 이 문서는 **확정한 규칙**만 적었다. 실제 자원의 총량, 운영 몫의 크기, 사용자 수 같은 규모 정보는 이 저장소에 쓰지 않는다.
>
> 함께 읽을 문서: [21번(팀과 역할)](../rules/team-ownership.md) · [기능별 정책](feature-policies.md)

## 1. 한도는 개수가 아니라 자원으로 센다

- 한도는 VM **개수**가 아니라 **CPU·RAM·SSD 할당량**으로 센다. 개수로 세면 자원이 많이 필요 없어도 최대 사양으로 여러 대를 만들 수 있다
- 실사용량이 아니라 **할당량**(VM 사양의 합계)으로 센다
- **꺼진 VM도 할당량으로 센다.** 꺼진 VM을 빼고 세면 그 사이 다른 VM이 자리를 채워서, 다시 켤 때 자원이 없을 수 있다
- VM 개수 상한은 없다. 자원 한도와 최소 사양이 대수를 제한한다

### 할당 상한 (전체 자원 대비)

| 자원 | 상한 | 이유 |
|---|---|---|
| RAM | 물리 용량의 1배 (초과 할당 없음) | RAM이 병목이다. VM은 할당받은 RAM의 상당 부분을 실제로 쓴다 |
| CPU | 물리 CPU의 2배까지 | CPU는 RAM보다 초과 할당의 위험이 작다 |
| SSD | 풀 용량의 80%까지 | thin 풀이 가득 차면 VM 디스크에 쓰기 오류가 나서 데이터가 깨질 수 있다. 나머지 20%는 스냅샷 공간이다 |

## 2. 자원을 나누는 순서와 비율

1. 운영 인프라와 관리자 VM 몫을 먼저 뗀다
2. 서비스 몫(서버리스·데이터베이스·원터치 배포가 쓰는 자원)을 뗀다
3. 나머지를 **일반 사용자 50 : 팀 50**으로 나눈다

- 50 : 50으로 시작하고, 운영하면서 확인해 조정한다
- 운영·관리자 몫은 v2 출시 직전에 실제로 재서 정한다
- 서비스 몫의 크기는 서비스 설계 뒤에 정한다 (**미정**)
- 사용자가 서비스로 쓰는 양(DB 개수·용량, 함수·앱 개수 등)은 **VM 한도에서 빼지 않고** 서비스별로 따로 제한한다. 서비스를 써도 VM 한도가 똑같이 깎이면 VM 대신 서비스를 쓸 이유가 없기 때문이다

## 3. 일반 사용자 1인 한도

**vCPU 4개, RAM 8 GiB, SSD 30 GiB**로 고정한다. 세 자원을 각각 따로 센다.

- 일반 사용자 한 명이 가진 개인 VM의 할당량 합계가 이 값을 넘을 수 없다
- 팀 VM은 팀 앞으로 세므로 이 한도에 들어가지 않는다
- **일반 몫이 다 차면 새 생성을 막는다.** 일반 사용자 개인 VM의 할당량 합계가 일반 몫(전체의 50%)에 닿으면, 그 사람의 1인 한도가 남아 있어도 새 개인 VM을 만들 수 없다
- **사양을 키울 때(11번 사양 변경)도 같은 규칙이다.** 1인 한도나 일반 몫 전체 상한을 넘으면 거부한다
- **관리자의 개인 VM에는 1인 한도를 적용하지 않는다.** 관리자 VM은 "운영 인프라 + 관리자 VM" 몫에 들어간다. 관리자 개인 VM에도 만료가 있고 팀 VM과 같은 주기다

## 4. 팀 한도

- 팀 VM은 만든 사람이 아니라 **팀 앞으로** 센다. 팀장이 VM을 만들어도 팀장 개인 몫은 줄지 않는다
- **팀 할당량은 모든 팀에 같다: vCPU 8개 · RAM 16 GiB · SSD 60 GiB** (1인 한도의 2배). 배포 없이 바꿀 수 있는 설정값이다. 팀 생성이 승인되면 적용된다
- 팀 VM 할당 합계가 팀 몫(전체의 50%)에 닿으면, 그 팀의 할당량이 남아 있어도 만들 수 없다
- 승인 대기 중인 팀은 VM을 만들 수 없다

## 5. VM 사양

- 티어 대신 **슬라이더**로 CPU·RAM·SSD를 직접 정한다
- **슬라이더 단위는 vCPU 1개, RAM 1 GiB, SSD 1 GiB다.** 화면 표시는 "GB"지만 값은 1024 단위(GiB)다. 운영체제 최소값은 이 단위로 올림한다. 1인 한도가 작아서 여러 VM에 나눠 쓰려면 1 단위가 필요하다
- **단위는 1024 단위다.** RAM 8 GiB = 8,192 MiB, SSD 30 GiB = 32,212,254,720 바이트다. Proxmox는 RAM을 MiB 정수로 받고 디스크 크기의 `G`를 GiB로 해석하므로, RAM은 `8192`, 디스크는 `30G`로 반올림 없이 넣는다. VM 안의 `free -h`도 1024 단위(`Gi`)로 표시하므로 사용자가 보는 숫자와 맞는다. 1000 단위로 주면 VM 안에서 8 GB가 약 7.45 Gi로 보인다
- **최소 사양**
  - RAM과 SSD는 사용자가 고른 운영체제의 공식 최소 기준이다. 운영체제마다 값이 다르다
  - vCPU는 1개다
  - GSMSV는 cloud-init 클라우드 이미지로 VM을 주므로, 공식 문서에 클라우드 이미지 값이 있으면 그 값을 쓴다. 공식 문서의 GB는 GiB로 읽는다
  - SSD 최소값은 템플릿 디스크 크기보다 작을 수 없다. Proxmox는 디스크를 줄이는 것을 지원하지 않기 때문이다 (실제 최소 SSD = 운영체제 최소 저장 공간과 템플릿 디스크 크기 중 큰 값)
- **고를 수 있는 운영체제**: Ubuntu 22.04 LTS, Ubuntu 24.04 LTS, Debian 13

| 운영체제 | RAM 최소 | 저장 최소 | 출처 |
|---|---|---|---|
| Ubuntu 22.04 LTS | 1 GB | 4 GB | 22.04 전용 공식 값이 없어 24.04 클라우드 이미지 값을 쓴다 |
| Ubuntu 24.04 LTS | 1 GB | 4 GB | [Ubuntu Server 문서](https://ubuntu.com/server/docs/reference/installation/system-requirements/) |
| Debian 13 | 512 MB | 4 GB | [Debian 설치 안내서 3.4](https://www.debian.org/releases/trixie/amd64/ch03s04.en.html) |

- 디스크(SSD)는 **늘리기만** 할 수 있다. 늘린 뒤 재부팅하면 cloud-init이 루트 파티션과 파일시스템을 자동으로 넓힌다

## 6. 노드는 시스템이 자동으로 배분한다

- 사용자는 노드를 고르지 않는다. 시스템이 자원이 많이 남은 곳에 배분한다
- 사양을 바꿀 때 그 VM이 있는 곳에 자리가 없으면 거절한다. VM을 다른 노드로 옮기기 어렵기 때문이다
- 그래서 한 번 배치한 VM은 그 자리에 계속 있고, 비율을 바꾸면 새 VM부터 적용된다
- 클론은 같은 노드 안에서만 되므로 OS 템플릿이 모든 노드에 있어야 한다

## 7. 정하지 않은 것

| 항목 | 정하는 사람 |
|---|---|
| 서비스 몫의 크기와 조정 방법 | 기획 (서비스 설계 뒤) |
| 운영·관리자 몫의 크기 | 출시 직전 실측으로 정한다 |
| 일반 사용자 수에 따른 1인 한도 조정 | 하지 않는다 (고정 한도로 대신한다) |
