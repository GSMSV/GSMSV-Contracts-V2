# 기능별 정책 (확정)

> 기능별로 정한 정책을 모았다. 기능은 번호와 이름을 함께 쓴다. 서비스(서버리스·데이터베이스·원터치 배포)는 [services](../services/)에, 팀과 권한은 [rules](../rules/)에 따로 있다.
>
> 표기: 따로 표시가 없으면 **확정**이다. 정하지 않은 것은 **미정**이라고 적었다.

## 1번(로그인)

- 로그인 화면에 역할 토글을 두지 않는다. 한 사람은 계정 하나를 갖고, 역할(USER/ADMIN)은 계정의 속성이다. 프로젝트 오너 역할을 없앴으므로([21번](../rules/team-ownership.md)) 역할을 고르는 토글의 이유가 사라졌다
- 관리자 지정과 회수는 관리자 화면에서 다른 관리자가 하고, 모두 감사 로그에 남긴다
- 졸업이 반영되면 일반 사용자는 GSMSV를 쓸 수 없다. **관리자 계정은 졸업해도 계속 쓸 수 있다**
- 재학 검증은 로그인할 때와 토큰을 갱신할 때 모두 한다. 졸업이 반영되면 늦어도 액세스 토큰 수명 안에 끊긴다
- 졸업생: 개인 VM은 졸업 전에 안내하고, 졸업 뒤에는 만료 주기대로 정리한다. 팀에서는 탈퇴로 처리하고, 팀장이었으면 [팀장 승계 규칙](../rules/team-ownership.md)을 따른다

## 5번(인스턴스 생성)

- **개인 VM 생성 화면과 팀 VM 생성 화면을 따로 둔다.** VM을 만들 때 헷갈리지 않게 하려는 것이다
- **생성 진행 표시는 단계 방식이다**: 대기 중(앞에 N명) → 복제 중 → 설정 중 → 부팅 중 → 네트워크 등록 중 → 완료. Go가 Kotlin에 단계를 보고하고 Kotlin이 브라우저에 SSE로 보낸다. 실패하면 어느 단계에서 왜 실패했는지 보여 준다 ([Kotlin·Go 경계](kotlin-go-boundary.md))
- 생성을 실행하는 방식(링크드 클론, 워밍 풀 등)은 개발 중에 정한다

## 6번(인스턴스 현황 확인)

- 팀 VM의 사용 목적은 팀장·DevOps만 고친다. 사용 목적은 사양·OS와 같은 VM 설정값이기 때문이다
- 초기 비밀번호는 계속 조회할 수 있다. 조회할 때마다 감사 로그에 남기고, 화면에 비밀번호 변경과 SSH 키 사용을 권하는 안내를 단다

## 8번(인스턴스 사용 기간 관리)

- **개인 VM**은 생성 후 **14일** 뒤 만료되고, 만료 7일 전부터 14일씩 연장할 수 있다
- **팀 VM**의 "첫 달"은 VM마다 그 VM의 생성 시각부터 **31일**이다. 첫 달이 지나면 2주마다 연장 신청을 한다. 팀 VM의 연장 신청 시점은 **미정**이다
- 연장하지 않으면 개인·팀 모두 **만료 즉시 정지 → 3일 유예 → 삭제**다. 유예 중에도 연장할 수 있다
- 연장 기준점은 "지금"과 "기존 만료일" 중 **늦은 쪽**이다. 기존 만료일 기준이면, 만료 3일이 지난 VM을 14일 연장해도 11일만 남는다
- 만료 알림은 7일 전, 3일 전, 1일 전, 정지할 때, 삭제할 때 보낸다
- 관리자 개인 VM도 팀 VM과 같은 주기로 만료된다
- 연장 횟수에는 제한이 없다. 1인 한도가 고정이라 오래 써도 한 사람이 쓰는 양은 늘지 않는다

## 9번(인스턴스 스냅샷 관리)

- 자동 스냅샷 켜기·끄기는 팀장·DevOps만 한다 (VM 설정값)
- API는 지금 값을 뒤집는 방식이 아니라 **원하는 상태를 지정하는 방식**으로 한다. 뒤집는 방식은 두 번 누르면 원래대로 돌아간다

## 10번(인스턴스 삭제)

- 삭제 전에 **VM 이름을 정확히 입력해야 삭제 버튼이 켜지는 확인 창**을 띄운다
- 팀 VM을 삭제하면 팀원 전원에게 알린다

## 11번(인스턴스 사양 변경)

- 디스크(SSD)는 **늘리기만** 할 수 있다. 1인 한도와 팀 할당량 안에서 늘린다. 디스크는 줄일 수 없다
- 늘린 뒤 재부팅하면 cloud-init이 루트 파티션과 파일시스템을 자동으로 넓힌다. 사양 규칙은 [할당량](quota.md)에 있다

## 19번(알림)

- **필수 알림**(만료 임박, 만료 정지, 삭제 예고, 삭제 완료)은 **학교 이메일**로 보낸다. 사이트 안 알림과 함께 보내며, 사용자가 끌 수 없다
- Discord: 계정 연결 기능을 새로 만든다. 연결은 선택이다. 연결한 사람에게만 Discord로도 보낸다
- 나머지 알림(생성 완료·실패, 문의 답변)은 사이트 안 알림을 항상 보내고, 이메일과 Discord(연결한 경우)는 사용자가 켜고 끈다
- 알림 보관은 15일, 최대 50건이다
- 이유: 중요한 알림이 놓치기 쉬워서 필수 알림은 사이트 밖(이메일)으로도 보낸다

## 21번(팀)

- 팀 만들기, 승인, 초대, 거절 처리의 규칙은 [팀과 역할](../rules/team-ownership.md)에 있다

## 28번(서비스 상태 공개)

- 감시 도구는 GSMSV 밖의 서버에 둔다. GSMSV가 멈췄을 때도 상태를 알려야 하기 때문이다
- 공개 상태 페이지에 구성요소별 상태(웹 콘솔, API, VM 생성, SSH 접속, HTTPS 도메인)와 장애 이력을 보여 준다

## 29번(GSMSV CLI)

- 언어는 Node이고 npm으로 배포한다
- 로그인은 기기 인증 방식(OAuth 2.0 Device Authorization Grant, RFC 8628)이다

## 31번(인스턴스 이미지 종류 늘리기)

- 고를 수 있는 운영체제는 Ubuntu 22.04 LTS, Ubuntu 24.04 LTS, Debian 13이다. 클라우드 이미지 템플릿을 모든 노드에 똑같이 올린다

## 32번(docs 추가)

- 사용자 가이드는 웹 콘솔의 `/docs`에 둔다
- 내부 개발 문서는 v2 저장소의 README·CONTRIBUTING과 이 저장소에 둔다
- 문서 피드백은 20번(문의 등록·답변)과 합친다

## 33번(테스트 환경 구축)

- 테스트 환경은 운영과 완전히 분리한다
- 개발자 로컬에서는 Go 서비스의 **가짜 모드**(인프라 없이 뜨는 모드)를 쓰고, CI는 **실제 PostgreSQL**로 돌린다. 인메모리 가짜 DB로 돌리면 PostgreSQL에만 있는 기능(advisory lock 등)을 한 번도 검증하지 못한다
