# 24번(DBaaS) — 데이터베이스 발급 서비스 기획 요약

> 이 문서는 **확정한 기획의 요약**이다. 구현 세부(API 구조, 상태 이름, 서버 실행 방식)는 담당이 개발하면서 정한다.
>
> 함께 읽을 문서: [21번(팀과 역할)](../rules/team-ownership.md) · [22번(권한 판단)](../rules/authorization.md) · [23번(자원 이름 규칙)](../rules/resource-naming.md) · [할당량](../policies/quota.md)

## 1. 무엇을 하는 서비스인가

학생이 VM 안에 데이터베이스를 직접 설치하지 않고, GSMSV에서 데이터베이스를 발급받아 쓴다.

- 개인 VM의 자원 한도가 작아서, 학생이 VM 대신 서비스를 쓰게 하는 것이 방향이다
- 엔진은 **MySQL을 먼저** 만들고 **PostgreSQL을 두 번째**로 더한다. 두 번째 엔진을 붙이면서 새 서비스를 빨리 추가할 수 있는 구조인지 검증한다
- 격리 방식은 **혼합형**이다
  - **공유형**(기본): DB 서버 하나를 여러 학생이 함께 쓰고, 학생마다 database와 계정을 나눠 준다
  - **전용형**: 격리가 꼭 필요한 **팀만** 관리자 승인을 받아 DB 서버 하나를 통째로 받는다. 개인은 전용형을 받을 수 없다

용어

| 용어 | 뜻 |
|---|---|
| DB 서버 | MySQL이나 PostgreSQL 프로그램 하나가 돌아가는 것. 그 안에 database가 여러 개 들어갈 수 있다 |
| database | DB 서버 안에서 테이블을 담는 단위 |
| 계정 | DB 서버에 접속하는 사용자. 어느 database에 무엇을 할 수 있는지가 계정의 권한이다 |
| DB 자원 | GSMSV가 발급하고 세는 단위. id가 `db-`로 시작한다 |

## 2. 누가 무엇을 할 수 있는가

| 동작 | 개인 DB | 팀 DB |
|---|---|---|
| 발급(공유형) | 본인 | 팀장·DevOps |
| 전용형 신청 | 할 수 없음 | 팀장·DevOps |
| 삭제 | 본인 | 팀장·DevOps |
| 설정 변경(비밀번호 교체 포함) | 본인 | 팀장·DevOps |
| 백업에서 복원 | 본인 | 팀장·DevOps |
| 접속 정보·비밀번호 보기 | 본인 | 팀원 전원 |
| 웹 쿼리 콘솔 | 본인 | 팀원 전원 |
| 백업 내려받기 | 본인 | 팀원 전원 |
| 사용 기간 연장 신청 | 본인 | 팀원 전원 |

- 팀 DB의 권한은 팀 VM과 같다: 만들기·지우기·설정은 팀장·DevOps, 접속 정보는 팀원 전원
- 복원은 지금 데이터를 덮어쓰는 파괴적인 동작이라 삭제와 같은 수준(팀장·DevOps)으로 둔다
- **관리자**는 전용형 신청을 승인하거나 거절하고, 삭제된 DB의 백업이 남아 있는 동안 복구 요청을 처리한다. 그 밖의 동작도 "관리자는 모든 동작 허용" 규칙으로 할 수 있다
- **시스템(자동)**: 용량 측정과 쓰기 금지·해제, 매일 백업, 만료 처리, 졸업 정리, 알림
- **GSMSV 권한이 닿지 않는 곳**: 학생이 DB 계정으로 직접 접속해서 하는 일(테이블 만들기, 데이터 넣기·지우기)은 그 계정의 DB 권한 안에서 자유다. 비밀번호를 아는 팀원은 일반 팀원이어도 DB에 직접 접속해 데이터를 지울 수 있다. 콘솔의 "삭제" 권한과는 별개이며 팀 VM과 같은 한계다

## 3. 자원 단위와 이름

- **공유형**: 공유 DB 서버 안의 **database 1개 + 그 database만 쓸 수 있는 계정 1개**를 DB 자원 1개로 센다
  - 학생이 database를 직접 만들 수 없다. 개발용과 테스트용이 따로 필요하면 DB 자원을 2개 받는다
  - 이유: GSMSV가 database를 하나하나 알아야 개수 한도가 실제 개수와 같고, 용량을 database마다 잴 수 있고, 지울 때 database와 계정을 함께 지워 남는 것이 없다
- **전용형**: **DB 서버 1개**를 DB 자원 1개로 센다. 그 안의 database와 계정은 팀이 직접 만든다. 자기 서버 안의 관리자 권한은 주지만, DB가 도는 컨테이너·노드의 권한은 주지 않는다. 팀이 서버 안에서 만든 계정과 database는 GSMSV가 알지 못하고 세지 않는다
- id는 `db-` 뒤에 무작위 12자다. GRN 예: `grn:team-4p8w2k9m1xza:db-k3m9x2p7q4ta`
- **서버에 실제로 만드는 database 이름과 계정 이름은 둘 다 db id 그대로** 쓴다
  - 이유: GSMSV가 관리하는 기술용 이름에는 바뀌지 않는 값(id)만 쓴다는 [23번 층 규칙 3](../rules/resource-naming.md) 때문이다. 학생이 지은 이름(`name`)을 서버의 이름으로 쓰면 이름을 바꿀 때마다 서버까지 바꿔야 한다
  - 받아들인 불편: id에 하이픈이 들어 있어서 SQL에서 이 이름을 쓸 때마다 따옴표로 감싸야 한다. 사용자 문서에 따옴표 예시를 넣는다
- 하위 자원: **백업**(접두사 `backup`). 예: `grn:team-4p8w2k9m1xza:db-k3m9x2p7q4ta/backup-3x7q9m4k`
- 개인 DB와 팀 DB는 서로 바꾸지 않는다

## 4. 발급과 신청

- **공유형**: 한도 안이면 승인 없이 바로 발급한다
- **전용형**: 팀장·DevOps가 **이유**(서버 설정·확장 기능 / DB 관리자 권한 / 성능 분리 중 선택)와 설명을 적어 신청하고, 관리자가 승인한다
  - 거절하면 사유를 반드시 적고 팀장에게 알린다. 신청은 "거절됨" 기록으로 남기고, 팀은 다시 신청할 수 있다
  - 전용형은 팀당 최대 1개이고, 사양은 한 가지로 고정한다 (사양 값은 서비스 자원 몫을 정할 때 함께 정한다)
- **승인 대기 중인 팀은 공유형·전용형 모두 만들 수 없다**

## 5. 접속

- **학생 VM에서**: DB 포트만 열고 **TLS를 필수**로 해서 접속한다
- **학생 PC(인터넷)에서는 직접 접속할 수 없다.** DB를 인터넷에 열지 않는다. VM을 거치는 SSH 터널을 사용자 문서에 안내한다
- **서버리스 함수·앱에서**: 함수·앱 설정에서 자기 DB를 고르면 GSMSV가 접속 정보를 Kubernetes Secret으로 넣어 준다. DB 비밀번호를 교체하면 함수·앱이 자동으로 갱신된다 ([서버리스](serverless.md), [원터치 배포](one-touch-deploy.md))
- 서비스 쪽에서 DB로 가는 길의 원칙은 [구조 개요 7장](../architecture/overview.md)에 있다

## 6. 비밀번호

- GSMSV가 무작위로 만든다. 사용자가 직접 정하지 않는다
- 다시 보여 줘야 하므로 해시가 아니라 **암호화해 저장**한다. 언제든 다시 볼 수 있고, **볼 때마다 감사 로그에 남긴다**
- 교체할 수 있다(개인은 본인, 팀은 팀장·DevOps). 교체하면 그 계정의 기존 연결을 끊는다
- 팀원이 팀을 나가면 팀장·DevOps에게 교체를 권하는 알림을 보낸다. **자동으로 교체하지는 않는다**

## 7. 사용량 한도 (모두 배포 없이 바꿀 수 있는 설정값)

- 개수: 개인 **2개**, 팀 **4개**(전용형 포함)
- 공유형 용량: 소유자별 합계로 개인 **1 GiB**, 팀 **2 GiB**
- 동시 연결: 계정당 **10개**
- DB 사용량은 VM 한도와 따로 센다. 백업 공간은 사용자 용량에 넣지 않는다
- **용량을 넘으면**: 80%와 100%에서 알린다. 넘으면 그 소유자의 DB를 **쓰기 금지**로 바꾼다 (읽기, `DELETE`, `TRUNCATE`, `DROP TABLE`은 허용). 한도 아래로 내려가면 자동으로 푼다. 전용형에도 같은 규칙을 건다

## 8. 백업과 복원

- 백업은 **매일 1회**, **7일 보관**한다. 공유형은 database마다, 전용형은 서버 통째로 한다. DB가 도는 곳과 다른 곳에 둔다
- 사용자가 직접 만드는 백업은 없다. 매일 자동 백업과 복원 직전 자동 백업 두 종류다
- **복원**은 같은 DB에 덮어쓴다. 복원 직전 상태를 백업으로 남기고, DB 이름을 입력해야 버튼이 켜지는 확인 창을 띄운다
- 백업 내려받기는 본인(팀 DB는 팀원 전원)이 할 수 있다
- 삭제된 DB의 백업은 보관 기간(7일)까지 남기고, 그 안에는 관리자에게 복구를 요청할 수 있다

## 9. 웹 쿼리 콘솔

- 개인 DB는 본인, 팀 DB는 팀원 전원이 쓴다
- **항상 그 DB의 계정으로 실행한다** (GSMSV 관리자 계정 금지). 계정 권한 안의 모든 SQL을 실행할 수 있다
- 쿼리당 **45초**, 결과는 **1,000행 또는 1 MiB**까지
- 감사 로그에는 **실행했다는 사실만** 남기고 SQL 본문과 결과는 저장하지 않는다
- 전용형에는 1차에서 웹 쿼리 콘솔을 주지 않는다

## 10. 수명

- 공유형·전용형 모두 VM 사용 기간 규칙을 그대로 따른다 ([기능별 정책](../policies/feature-policies.md))
- **정지**는 계정 잠금과 기존 연결 끊기이고, 데이터는 남긴다. 연장하면 다시 접속된다
- 졸업이 반영되면 개인 DB를 정지 → 3일 유예 → 삭제한다
- 팀을 해체하면 팀 DB를 모두 삭제한다

## 11. 알림

- 용량 80%·100%, 만료·정지·삭제, 쓰기 금지 해제, 전용형 승인·거절을 알린다
- 팀 DB 알림을 받는 사람의 범위는 아직 정하지 않았다 (팀 VM과 같이 팀원 전원에게 보내는 안을 제안한다)

## 12. 하지 않는 것

- 인터넷(학생 PC)에 DB 포트를 열지 않는다
- 개인에게 전용형을 주지 않는다
- 공유형 계정에 DB 관리자 권한이나 database를 만드는 권한을 주지 않는다
- 서버 쪽 database·계정 이름에 사용자가 지은 이름이나 이메일을 넣지 않는다
- 웹 쿼리 콘솔을 GSMSV 관리자 계정으로 실행하지 않는다. 콘솔의 SQL 본문과 결과를 저장하지 않는다
- 비밀번호를 해시로만 저장하지 않는다
- 팀원이 나갈 때 비밀번호를 자동으로 바꾸지 않는다
- 백업 공간을 사용자 용량 한도에 넣지 않는다. DB 사용량을 VM 한도에서 빼지 않는다
- **1차 범위에서 만들지 않는 기능**: 덤프 파일 올려서 가져오기 / 엔진 버전 고르기(엔진마다 GSMSV가 정한 버전 하나) / 개인 DB ↔ 팀 DB 전환 / 전용형 사양 바꾸기 / 공유형 → 전용형 데이터 옮겨 주기 / 읽기 복제본·고가용성 / 스키마·마이그레이션 도구 / 전용형의 웹 쿼리 콘솔

## 13. 완료 판정

- 학생이 VM에 DB를 설치하지 않고, 발급받은 접속 정보만으로 자기 VM에서 MySQL(나중에 PostgreSQL)에 TLS로 접속해 테이블을 만들고 쓸 수 있다
- 공유형 학생 A의 계정으로 학생 B의 database에 접근하면 거부된다. 웹 쿼리 콘솔에서도 같다
- 개인이 공유형 DB를 2개 가진 상태에서 3번째를 요청하면 거부되고, 한도와 쓰고 있는 개수가 안내된다
- 소유자의 공유형 DB 크기 합계가 한도를 넘으면 `INSERT`가 실패하고 `SELECT`·`DELETE`·`TRUNCATE`·`DROP TABLE`은 된다. 한도 아래로 내려가면 다시 `INSERT`가 된다
- 한 계정으로 11번째 동시 연결을 열면 거부된다
- 비밀번호를 교체하면 옛 비밀번호로 붙어 있던 연결이 끊기고, 옛 비밀번호로 새로 접속하면 실패한다
- 인터넷에서 DB 포트에 접속할 수 없다
- 팀 DB의 접속 정보를 일반 팀원도 볼 수 있고, 볼 때마다 감사 로그가 남는다. 일반 팀원이 삭제·복원·비밀번호 교체를 요청하면 403을 받는다
- 웹 쿼리 콘솔에서 45초가 넘는 쿼리는 중단되고, 결과는 1,000행이나 1 MiB에서 잘린다. 감사 로그에 SQL 본문이 없다
- 백업이 매일 만들어지고 7일 뒤 사라진다. 복원하면 고른 시점으로 돌아가고, 복원 직전 상태가 백업으로 남는다
- 만료되면 접속이 막히고 붙어 있던 연결이 끊기며 데이터는 남는다. 3일 유예 안에 연장하면 다시 접속된다
- 팀을 해체하면 팀 DB가 모두 삭제된다

## 14. 정하지 않은 것

| 항목 | 정하는 사람 |
|---|---|
| 상태 이름과 칸 구성, API 구조 | 백엔드 담당 |
| 전용형 서버의 실행 방식과 사양 값 | 인프라 담당 |
| 호스트 이름의 형식 (노드를 드러내지 않는 값) | 인프라 담당 |
| 사용자에게 보이는 이름(`name`)의 규칙 | 백엔드 담당 |
