# 15·16·17번(서버리스) — 서버리스 함수 서비스 기획 요약

> 이 문서는 **확정한 기획의 요약**이다. 구현 세부(API 구조, 상태 이름, 실행 환경 구성)는 담당이 개발하면서 정한다.
>
> 15번은 함수 관리, 16번은 함수 실행, 17번은 함수 실행 로그 확인이다.
>
> 함께 읽을 문서: [21번(팀과 역할)](../rules/team-ownership.md) · [22번(권한 판단)](../rules/authorization.md) · [23번(자원 이름 규칙)](../rules/resource-naming.md) · [데이터베이스](database.md) · [원터치 배포](one-touch-deploy.md)

## 1. 무엇을 하는 서비스인가

VM을 띄우지 않고 코드 조각(함수)만 올려 두면, 요청이 들어오거나 정해진 시각이 됐을 때 GSMSV가 실행해 준다.

- v2에서도 서버리스를 유지하고, **처음부터 다시 만든다.** 이유: 개인 VM 한도가 작아서 학생이 VM 대신 서비스를 쓸 수밖에 없다
- **범위는 "짧게 끝나는 함수"다.** 요청 하나나 예약 한 번을 처리하고 끝난다. 실행과 실행 사이에 상태를 들고 있지 않는다. 계속 떠 있어야 하는 웹 앱은 [원터치 배포](one-touch-deploy.md)가 맡는다
- **실행 경로는 세 가지다**: 수동 실행(콘솔 테스트), HTTP 트리거, 예약 트리거. 다른 경로(DB 변경, 파일 업로드 같은 이벤트)는 지금 GSMSV에 연결할 이벤트가 없어 두지 않는다

용어

| 용어 | 뜻 |
|---|---|
| 함수 | 학생이 올린 코드와 그 설정. id가 `fn-`로 시작하는 서비스 자원이다 |
| 트리거 | 함수를 언제 실행할지 정하는 것. HTTP와 예약 두 종류. 함수의 하위 자원이다 |
| 실행 환경 | 함수 코드가 실제로 도는 샌드박스 컨테이너 |
| 호출 주소 | HTTP 트리거의 공개 주소 |
| 버전 | 함수를 저장할 때마다 남는 코드·설정 사본 |

## 2. 누가 무엇을 할 수 있는가

| 동작 | 개인 함수 | 팀 함수 |
|---|---|---|
| 코드·설정·트리거·버전·실행 로그 보기 | 본인 | 팀원 전원 |
| 만들기, 지우기 | 본인 | 팀장·DevOps |
| 코드·설정 수정, 활성·비활성 바꾸기 | 본인 | 팀장·DevOps |
| 트리거 만들기·고치기·지우기, 호출 주소 재발급 | 본인 | 팀장·DevOps |
| 사용자 지정 도메인 연결·해제 | 본인 | 팀장·DevOps |
| 버전 되돌리기 | 본인 | 팀장·DevOps |
| 수동 실행 | 본인 | 팀장·DevOps |
| 실행 로그 삭제 | 본인 | 팀장·DevOps |
| 사용 기간 연장 신청 | 본인 | 팀원 전원 |

- 이유: 코드·런타임·환경변수·실행 제한은 함수의 **설정값**이고, 설정값은 팀장·DevOps만 고친다 (팀 VM의 사용 목적과 같은 규칙). 수동 실행은 DB에 쓰는 것 같은 부작용이 있을 수 있어서 일반 팀원이 VM 전원 제어를 못 하는 것과 같은 수준으로 둔다
- 받아들인 불편: 일반 팀원은 코드를 고칠 수 없다. 함께 개발할 팀원에게는 팀장이 DevOps 역할을 준다
- **함수를 관리하는 요청은 22번 권한 판단을 거친 API에서만 받는다**
- 관리자는 "관리자는 모든 동작 허용" 규칙으로 모든 동작을 할 수 있다. 목록과 상세에서 규칙이 달라지지 않는다 (자원 로더 하나로 판단)
- 시스템(자동): 예약 실행, 실행 환경 재사용·정리, 하루 실행 횟수 세기, 실행 로그 자동 삭제, 만료 처리, 졸업 정리, 알림
- **GSMSV 권한이 닿지 않는 곳**: HTTP 트리거의 호출 주소는 공개다. 주소를 아는 누구나 호출할 수 있다. 함수 안에서 무엇을 검사할지는 학생의 몫이다. 일반 팀원도 코드와 일반 환경변수를 볼 수 있다. 비밀 변수의 값은 누구에게도 다시 보이지 않는다

## 3. 자원 구조

- id는 `fn-` 뒤에 무작위 12자다. GRN 예: `grn:team-4p8w2k9m1xza:fn-6d2r8t5y3n7e`
- 함수 이름은 `name`에만 둔다. **호출 주소에는 함수 id도 이름도 넣지 않는다** (이름을 바꿔도 주소가 바뀌지 않게)
- **개인 함수 ↔ 팀 함수 전환은 하지 않는다**
- 하위 자원

| 하위 자원 | 접두사 | 표기 예 |
|---|---|---|
| 트리거 (HTTP 또는 예약) | `trigger` | `grn:…:fn-…/trigger-5n3w7r2x` |
| 버전 | `version` | `grn:…:fn-…/version-9c4m6k2p` |
| 도메인 연결 (VM과 같은 종류) | `domain` | `grn:…:fn-…/domain-4k8m2q9t` |

- 트리거를 다루는 요청에서는 그 트리거가 요청에 적힌 함수의 것인지 확인한다 ([23번](../rules/resource-naming.md)의 부모 확인)
- 설정값: 함수는 코드, 런타임, 환경변수(변수마다 비밀 표시), 실행 제한(메모리·시간), 활성 여부, 연결한 DB, 사용 기간. 트리거는 HTTP면 받을 요청 방식과 호출 주소 토큰, 예약이면 cron 식
- 활성 여부는 "활성"·"비활성" 두 값만 받는다

## 4. 실행 방식

- 함수는 **강한 격리를 가진 샌드박스 컨테이너**에서 실행한다. 학생 코드를 돌리는 별도 노드 묶음에서 돌리고, [원터치 배포](one-touch-deploy.md)와 같은 종류의 격리를 쓴다
- 실행 환경은 **같은 함수 안에서만 잠깐 다시 쓴다.** 다른 함수와 같이 쓰지 않는다. 작은 임시 파일 공간을 준다
- 언어: **JavaScript, TypeScript, Python.** TypeScript는 저장할 때 컴파일하고, 실패하면 저장을 거부한다. 외부 패키지는 GSMSV가 고른 것만 미리 넣는다
- 서버리스 서비스 자체는 Kotlin·Go 안에서 만들고, 분담은 [Kotlin·Go 경계](../policies/kotlin-go-boundary.md) 담당이 정한다

## 5. HTTP 트리거와 호출 주소

- 호출 주소는 `https://{토큰}.{콘솔과 다른 별도 도메인}` 형태다. 함수 id·이름을 넣지 않는다
- **기본 공개**이고, 인증이 필요하면 함수 코드에서 요청 헤더를 직접 검사한다. 사용자 문서에 예시를 넣는다
- 주소를 **재발급**하면 옛 주소는 즉시 막힌다
- 하위 경로, 쿼리 문자열, 요청 헤더, 요청 본문을 함수에 넘긴다. 비활성 함수는 호출을 거부한다
- **사용자 지정 도메인**: 함수당 1개, DNS TXT 레코드로 소유를 확인한 뒤 연결한다

## 6. 예약 트리거

- 서울 시간대로 고정한다. 5칸 cron 식을 쓴다 (저장할 때 검사하고, 다음 실행 시각을 미리 보여 준다). **최소 간격은 5분**이다
- 비활성이면 실행하지 않는다. 매번 최신 코드를 쓴다. 함수를 지우면 트리거도 함께 지운다
- 서버가 여러 개여도 **한 번만 실행**한다
- 앞 실행이 끝나지 않았거나 놓친 실행은 건너뛰고 기록한다

## 7. 수동 실행

- 콘솔에서 테스트로 실행한다. 팀 함수는 팀장·DevOps만 한다

## 8. 사용량 한도 (모두 설정값)

| 항목 | 값 |
|---|---|
| 함수 개수 | 개인 3개, 팀 6개 |
| 함수당 트리거 | HTTP 1개, 예약 3개 |
| 실행 시간 | 기본 30초, 최대 60초 |
| 메모리 | 기본 128 MiB, 최대 256 MiB |
| 동시 실행 | 함수마다 2개 (넘으면 429) |
| 하루 실행 횟수 | 소유자별 개인 10,000회, 팀 20,000회 (80%·100%에서 알림) |
| 환경변수 | 합계 8 KB |

## 9. 네트워크

- 함수에서 바깥으로 나가는 통신은 **웹 포트(HTTP·HTTPS)만** 허용한다. 사설 대역, GSMSV 안쪽, 학생 VM으로는 나가지 못하게 막는다
- 함수 설정에서 **자기 DB([데이터베이스](database.md))를 고르면** GSMSV가 접속 정보를 Kubernetes Secret으로 넣어 준다. DB 비밀번호를 교체하면 자동으로 갱신한다
- 서버리스는 학생 VM을 부르지 않는다

## 10. 환경변수와 비밀값

- 변수마다 **비밀 표시**를 고른다. 비밀 변수의 값은 저장한 뒤 누구에게도 다시 보여 주지 않는다
- 실행 로그에 찍힌 비밀값은 가린다
- 목록 응답에는 코드와 환경변수를 넣지 않는다

## 11. 실행 로그 (17번)

- 요청·응답 본문은 저장하지 않는다
- 실행 기록과 함수 출력(1건당 8 KB)을 남기고, **7일 또는 1,000건**까지 둔다. 건너뜀·한도 초과 거부도 기록한다
- 조회는 100건씩, 삭제는 전체 삭제만 한다

## 12. 버전

- 코드·설정을 저장할 때마다 자동으로 만들고 **10개**를 보관한다
- 코드·런타임·실행 제한만 담고 환경변수는 담지 않는다
- 되돌리면 새 버전이 생긴다

## 13. 수명

- VM·DB와 같은 주기로 만료된다 ([기능별 정책](../policies/feature-policies.md))
- 정지는 **비활성**이다(세 실행 경로 모두 실행 안 함). 코드·설정은 남긴다
- 졸업·팀 해체는 [데이터베이스](database.md)와 같다
- 삭제할 때는 함수 이름을 입력하는 확인 창을 띄운다

## 14. 알림

- 하루 실행 한도 80%·100%, 만료·정지·삭제를 알린다
- 팀 함수 알림을 받는 사람의 범위는 아직 정하지 않았다 (팀 VM과 같이 팀원 전원에게 보내는 안을 제안한다)

## 15. 1차에서 하지 않는 것

- 파일 여러 개로 된 함수
- 실패 시 자동 재시도
- 함수끼리 잇기
- 실행 실패 알림
- 로그 내려받기

## 16. 정하지 않은 것

| 항목 | 정하는 사람 |
|---|---|
| API 구조, 상태 이름 | 백엔드 담당 |
| 함수 이름 규칙(글자·길이·예약어) | 백엔드 담당 |
| 실행 환경의 구성(네임스페이스 단위 등) | 인프라 담당 |
